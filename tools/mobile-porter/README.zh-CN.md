# Skyward 手机端移植工具（测试版）

作者：山轮料叉。运行环境：Android 11 以上、ARM64、已具备可授权的 `su`。APK 内置 1600 Fix50 donor 的 Recovery 程序、配置、MTP 规则和字体（含 MiSans；许可见应用资源），以及原生 ARM64 移植助手。不需要下载 donor、安装 Python 或连接电脑。1600 是 donor，不是整张用于覆盖本机的底包。

1. 在 APK 手动选择一加 Ace 竞速版（`acerace` / `PGZ110`）或 OPPO K10（`PGJM10`）。不会把普通 Ace 的 `ace` 代号识别为竞速版。
2. 点「授权 Root 并准备」。授予 Root 后，应用读取当前槽的原始 `vendor_boot` 和顶层 `vbmeta` 并保存两份全分区备份，再用本机原镜像重打包。目标的 DTB、bootconfig 和原厂模块不会换成 donor 版本。已修改的底包、不支持的格式或没有可核对的原厂直接 AVB 描述符会被拒绝。准备不写分区。
3. 分别通过系统文件保存器导出两份备份，留存到安全位置。你可以到这里停下。只有导出后，且在明确确认框点「确认刷入」，才写当前槽。
4. 刷入要求 Bootloader 已解锁，BootControl 确认当前槽和下次槽相同且无快照合并。先设置当前槽顶层 `vbmeta` 的 hashtree/verification 禁用标志，再写同槽 `vendor_boot`，两份分别同步并校验读回。不自动重启、切槽、清数据或处理其他分区。

**风险：** 修改顶层 `vbmeta` 会使原签名不再有效，解锁不保证 OEM 接受。两个分区不是原子写入，失败或断电可能留下部分写入；出现这类错误时不要直接重启。仅在能使用已知救援手段时尝试写入。APK 中两项选单共用同一引擎，实机仍按实际系统标识、分区、容量和 AVB 布局判断。当前只通过主机真实 PGZ110 .211 样本生成、AVB 差异检查、主机测试、ARM64 构建和 APK 签名校验，**没有在手机安装、授权 Root 或真实刷写验证，也没有验证 PGJM10 原厂样本**。
